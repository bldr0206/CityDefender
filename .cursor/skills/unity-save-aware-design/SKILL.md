# Unity Save-Aware Design

## Принцип

Любая новая gameplay-система должна сразу отвечать на вопрос: что из её состояния нужно сохранить и как это состояние восстановится после загрузки.

Не откладывай save-дизайн "на потом" для:

- динамических игровых сущностей;
- валют, ресурсов и инвентаря;
- состояния игрока;
- прогресса уровня, квестов, дверей, collectables, NPC и агентов;
- объектов, которые исчезают, перемещаются, открываются, покупаются, собираются или разрушаются.

## Где хранить состояние

- Глобальное игровое состояние хранить через `Game` как источник истины: текущий уровень, фаза, глобальная валюта, устойчивые player facts.
- События изменения состояния и команды save/load проводить через `Actions`.
- Файловую сериализацию не класть в `Game`: чтение/запись файлов остаётся в `SaveService`.
- Сбор и применение состояния уровня держать в save-controller уровня, например `LevelSaveController`.
- Приватные поля gameplay-компонентов не читать напрямую из save-системы. Добавлять маленький явный API: `GetMoney()`, `SetMoney(int)`, `CaptureSaveData()`, `RestoreSaveData(data)`.

## Динамические сущности

Если объект создаётся, исчезает или меняет состояние в runtime:

- добавить стабильный `SaveId` или совместимый save-идентификатор;
- сохранить prefab/source id, если объект нужно пересоздавать;
- сохранить `position`/`rotation`, активность, владельца/контейнер, прогресс действия и важные флаги;
- реализовать snapshot/restore рядом с владельцем состояния;
- при загрузке сначала создать/найти объект, потом применить сохранённые данные.

## Валюты и player state

- Все валюты, ресурсы, здоровье, инвентарь, способности и прочее player state проектировать как сохраняемые по умолчанию.
- Источник истины должен быть один: не дублировать деньги или флаги одновременно в UI, MonoBehaviour и static-полях.
- UI только отображает состояние и слушает события; он не должен быть местом хранения прогресса.
- Для Rigidbody-объектов восстанавливать позицию через Rigidbody API и синхронизировать физику.

## Перед завершением правки

Проверь отредактированный gameplay-код:

- Что именно должно попасть в сейв?
- Где источник истины этого состояния?
- Есть ли `SaveId` у scene/runtime объектов, которые переживают load?
- Есть ли явный `CaptureSaveData()` / `RestoreSaveData()` или другой понятный путь восстановления?
- Не добавлена ли новая валюта, progress-флаг или player state без save API?
- Не появилась ли файловая логика внутри `Game`, UI или случайного MonoBehaviour?

Если состояние не должно сохраняться, это должно быть осознанное runtime-only состояние: визуальный эффект, временная анимация, input cache, текущий tween, debug-only данные.
